# iOS 方案一：快捷指令（Shortcuts）

> 适用：iPhone / iPad，iOS 15 及以上（iOS 17 / 18 界面措辞略有差异，见文末）
> 成本：0 元，无需越狱、无需签名、无需电脑
> 效果：三条快捷指令覆盖 Android 端的日常操作——**登录 / 查状态 / 断开**，
> 均可添加到主屏幕，点图标即执行；配合自动化可实现「加入 SNNU 网络瞬间自动登录」

---

## 0. 为什么快捷指令能做到

校园网门户的登录、查状态、断开，本质是三次 HTTP 请求。src/portal.rs 的全部网络交互就是这段逻辑，
快捷指令的「获取 URL 内容」动作可以原样复现。

### 三条指令与上游端点对照

| 指令 | 方法 | 端点（8601 主端口） | 对应实现 |
| :--- | :--- | :--- | :--- |
| 校园网登录 | POST | `http://202.117.144.205:8601/snnuportal/login` | `portal.rs:755` login_unlocked |
| 校园网状态 | GET | `http://202.117.144.205:8601/snnuportal/userstatus.jsp` | `portal.rs:390` fetch_status_page |
| 校园网断开 | GET | `http://202.117.144.205:8601/snnuportal/logoff` | `portal.rs:908` logout |

> 断开走的是 `GET /snnuportal/logoff`（无尾部 .jsp、无查询串），与登录的 `/login` 是两条不同路径，
> 抄错一个字符就会 404。

### 登录请求形态（与 src/portal.rs 一致）

| 项 | 值 | 出处 |
| :--- | :--- | :--- |
| 方法 | POST | `portal.rs` 登录流程 |
| URL | `http://202.117.144.205:{port}/snnuportal/login` | HOST + `/snnuportal/login` |
| Content-Type | `application/x-www-form-urlencoded` | 同左 |
| Referer | `http://202.117.144.205:{port}/snnuportal/login.jsp` | 同左 |

### 表单字段（逐字一致，顺序不要改）

| 字段名 | 取值 | 说明 |
| :--- | :--- | :--- |
| sourceurl | `null` | 固定字符串 `null`，不是空值 |
| account | 你的学号 | |
| password | 你的密码 | 含特殊字符时见「手动正文」一节 |
| yys | `mobile` / `unicom` / 空 | 代拨运营商，留空＝校园网不代拨 |
| issave | 空字符串 | 固定留空 |

`yys` 取值对照（desktop_ui.rs 的运营商分段：校园网 / 移动 / 联通）：

| 界面选项 | yys |
| :--- | :--- |
| 移动 | `mobile` |
| 校园网（不代拨） | 留空 |
| 联通 | `unicom` |

> **注意**：`telecom`（电信）出口已停用。程序读到旧配置里的 `telecom` 会自动回落成空值（校园网）。
> 快捷指令里也请**不要**填 `telecom`，否则会认证失败。

### 端口

门户有 11 个端口可用，按顺序尝试：

```
8601  8602  8603  8605  8609  8604  8606  8607  8608  8610  8600
```

**首选 `8601`**，不通再依次换。下文三条指令的示例统一写 8601，备份端口用 8602。

## 1. 指令一「校园网登录」

打开「快捷指令」App → 右上角 `+` → 新建快捷指令 → 点顶部标题改名为 **校园网登录**。

### 动作清单

| # | 动作名 | 关键参数 |
| :--- | :--- | :--- |
| 1 | 获取网络详情 | 无需配置（首次运行需允许权限） |
| 2 | 如果 | 网络详情 → 网络名称 **不是** `SNNU` → 分支内「停止此快捷指令」 |
| 3 | 文本 | 学号 → 重命名变量 `学号` |
| 4 | 文本 | 密码 → 重命名变量 `密码` |
| 5 | 从菜单中选取 | 菜单项 `移动` / `校园网` / `联通` → 结果存入变量 `yys` |
| 6 | 获取 URL 内容 | `POST http://202.117.144.205:8601/snnuportal/login`，表单 5 行 |
| 7 | 如果 | 动作 6 输出 **包含** `当前登录账号` → 显示提醒「登录成功」 |
| 8 | 显示提醒 | 失败提示，插入动作 6 输出原文 |

### 逐步说明

#### 动作 1 · 获取网络详情

搜索 **「获取网络详情」**（Get Network Details）→ 添加。

- 首次运行会弹窗询问是否允许获取网络信息，选 **允许**。
- 输出对象里包含「网络名称」字段。

> 搜不到这个动作说明系统版本较老，可跳过动作 2 直接登录。登录本身幂等，不在校园网时只会失败，不产生副作用。

#### 动作 2 · 判断是不是 SNNU

添加 **「如果」**：

- 条件：网络详情 的 网络名称 **不是** `SNNU`
- 在「如果」分支内添加 **「停止此快捷指令」**
- 后面的登录动作放进「否则」分支

> `SNNU` 是程序默认 SSID（config.rs 的 wifi_ssid 默认值）。学校 SSID 不同就自行替换。

#### 动作 3 · 账号

添加 **「文本」**，内容填学号，然后把变量条重命名为 `学号`。

#### 动作 4 · 密码

再加一个 **「文本」**，内容填密码，重命名为 `密码`。

> 安全提示：这两个「文本」只存在本机快捷指令里，不会上传到任何服务器。
> 但要注意：① 开启 iCloud 同步会同步到你的 iCloud 账户；② 任何人拿到已解锁的手机都能直接看到明文密码。
> 介意的话改用「询问输入」每次手输，或关掉该快捷指令的 iCloud 同步。
> 参考 README「隐私与账号说明」：Windows 端用 DPAPI、Linux 端是 0600 权限的 base64（并非加密）。
> 快捷指令的「文本」动作同样是明文存放，安全边界由设备锁屏承担。

#### 动作 5 · 运营商（默认移动）

添加 **「从菜单中选取」**，依次建三个菜单项，**「移动」放第一位**（菜单没有真正的默认值，排第一就是最常用的那个）：

| 菜单项名称 | 分支内动作 | 最终 yys |
| :--- | :--- | :--- |
| 移动 | 「文本」内容填 `mobile` | `mobile` |
| 校园网 | 「文本」内容留空（空文本） | 空 |
| 联通 | 「文本」内容填 `unicom` | `unicom` |

每个分支末尾都加一个 **「设定变量」**，变量名 `yys`，值为该分支的「文本」。
菜单结束后（「结束菜单」之后）再放动作 6，用变量 `yys` 填表单。

> 嫌菜单麻烦可以退回最简写法：一个「文本」内容填 `mobile`，重命名为 `yys`。
> 代价是换运营商要进快捷指令里改文本。

#### 动作 6 · 获取 URL 内容（核心 POST）

搜索 **「获取 URL 内容」** → 添加，展开后设置：

| 界面项 | 设置 |
| :--- | :--- |
| URL | `http://202.117.144.205:8601/snnuportal/login` |
| 展开箭头 → 方法 | POST |
| 请求正文 | 表单（Form） |
| 请求头 | 添加 Referer = `http://202.117.144.205:8601/snnuportal/login.jsp` |

在「请求正文 → 表单」下依次添加 5 行（**字段名逐字照抄，大小写敏感**）：

| 键 | 值 |
| :--- | :--- |
| sourceurl | 手输：`null` |
| account | 变量 `学号` |
| password | 变量 `密码` |
| yys | 变量 `yys` |
| issave | 留空 |

> **坑位提醒**：部分 iOS 版本会丢弃「值为空」的表单行，导致 `issave` 缺失。若一直失败，改用下面的手动正文写法。

#### 动作 6-备用 · 手动拼正文

把动作 6 的「请求正文」改为 文本，内容填一整行：

```
sourceurl=null&account=2023xxxxxx&password=你的密码&yys=mobile&issave=
```

同时补请求头 Content-Type = `application/x-www-form-urlencoded`。

密码里若含 `&` `=` `+` `%` `#` 等字符，必须先做 URL 编码（用「URL 编码」动作处理密码变量，
或先把密码改成纯字母数字再测）。

#### 动作 7 · 判定成功 / 失败

添加 **「如果」**：

- 条件：动作 6 的输出 **包含** `当前登录账号`
- 真分支：**「显示提醒」**「登录成功」
- 假分支：**「显示提醒」**「登录失败，请检查账号密码或端口」，正文插入动作 6 的输出

> `当前登录账号` 就是 `portal.rs:12` 的 `MARK` 常量，程序判定在线用的也是这一个字符串。

到这里点「完成」，手动运行一次确认能登录成功。

### 可选增强 · 登录前先查状态

在动作 6 之前插入 **「运行快捷指令」** → 选 **校园网状态**，或直接插一个
**「获取 URL 内容」** `GET http://202.117.144.205:8601/snnuportal/userstatus.jsp`，
再用 **「如果」** 判断内容 **包含** `当前登录账号` → 显示「已在线」并「停止此快捷指令」。

未登录时门户会把 userstatus.jsp 重定向到登录页，与程序的 status 判定一致。

## 2. 指令二「校园网状态」

对应 Android 端的「查在线状态」：显示**是否在线 / 账号 / IP / 登录时间**。

新建快捷指令，命名 **校园网状态**。

### 动作清单

| # | 动作名 | 关键参数 |
| :--- | :--- | :--- |
| 1 | 获取 URL 内容 | `GET http://202.117.144.205:8601/snnuportal/userstatus.jsp` |
| 2 | 匹配文本 | 正则 `id="account" value="([^"]*)"` → 账号（ASCII，抗乱码） |
| 3 | 匹配文本 | 正则 `id="ipaddr" value="([^"]*)"` → 当前 IP（ASCII，抗乱码） |
| 4 | 匹配文本 | 正则 `20\d{2}-\d{2}-\d{2} \d{2}:\d{2}:\d{2}` → 登录时间 |
| 5 | 如果 | 动作 2 的匹配结果 **有值** → 走在线分支（离线时该值为空串） |
| 6 | 显示结果 | 在线：`在线｜账号：{2}｜IP：{3}｜登录于：{4}` |
| 7 | 显示提醒 | 离线：`当前未登录`（或动作 1 的输出原文） |

### 逐步说明

#### 动作 1 · 取状态页

搜索 **「获取 URL 内容」** → URL 填
`http://202.117.144.205:8601/snnuportal/userstatus.jsp`，方法保持 GET。

备份端口把 `8601` 换成 `8602`。

> 这一步是**只读**请求，不会改变认证状态，随便跑。
> 若返回的是登录页 HTML（而不是状态表格），说明当前没在线——程序也是靠这个判断的。

#### 动作 2 · 提取「是否在线 + 账号」

添加 **「匹配文本」**，把动作 1 的输出作为输入，正则填：

```
id="account" value="([^"]*)"
```

**为什么用这个正则而不是匹配中文标签**：实测状态页里除了可见的
`<span class="zhengwen1">42512012@mobile</span>`，还有一组**隐藏输入框**：

```html
<input type="hidden" id="ipaddr"  value="10.138.108.230"/>
<input type="hidden" id="account" value="42512012@mobile"/>
```

这两个字段是**纯 ASCII 的 id + 值**，完全不受 gb2312 乱码影响——比匹配 `当前登录账号` 这类中文标签稳得多。
账号值形如 `学号@运营商`（`mobile` / `unicom`），顺带能看出当前走的是哪家代拨。

「匹配文本」返回的是**列表**，取第一个要用 **「从列表中获取项目」**（位置 第一个项目）。

> 离线时这两个隐藏框的 `value` 为空串，正则照样能匹配到（只是值为空），
> 所以动作 5 判「有值」时要判**非空**，不是判「匹配到没有」。

#### 动作 3 · 提取 IP

再加一个 **「匹配文本」**，正则：

```
id="ipaddr" value="([^"]*)"
```

和动作 2 同理，取隐藏框而不是可见的 `当前IP` 那一行——中文标签会乱码，`id` 不会。
校园网内网地址都是 `10.` 开头（实测为 `10.138.x.x`）。

> 兜底正则（万一门户改版去掉了隐藏框）：
> `10\.\d{1,3}\.\d{1,3}\.\d{1,3}`——纯数字，同样不受编码影响，但会同时匹配到
> 页面里其它 `10.x` 片段（例如 CSS 里的 `line-height` 之类不会命中，但脚本里的地址会），取第一个通常就是对的。

#### 动作 4 · 提取登录时间

再加一个 **「匹配文本」**，正则：

```
20\d{2}-\d{2}-\d{2} \d{2}:\d{2}:\d{2}
```

门户给的时间格式就是 `2026-10-25 14:06:29`（见 portal.rs 的 take_time）。

#### 动作 5 · 判断在线

添加 **「如果」**：动作 2 的匹配结果 **有任何值**（非空）。

在线时 `account` 是 `42512012@mobile` 这类值，离线时是空串——一个条件就够，
不需要再去匹配 `未登录`（中文，会受乱码影响）。

> 「如果」里选「匹配文本」的结果时，注意选的是**从列表取出的那个项目**，不是整个列表。

#### 动作 6 / 7 · 显示结果

在线分支用 **「显示结果」**（比「显示提醒」更适合展示多行文本）：

```
在线
账号：{动作 2 的匹配结果}
IP：{动作 3 的匹配结果}
登录时间：{动作 4 的匹配结果}
```

离线分支用 **「显示提醒」**：「当前未登录」，正文插入动作 1 的输出原文（方便排查是不是被重定向了）。

### 关于 gb2312 / HTML 源码的局限（务必读）

门户的状态页是老式 JSP，portal.rs 解码时是**先试 UTF-8、失败再按 GB18030 解**（`portal.rs:111` 的 decode）。
快捷指令的「获取 URL 内容」**没有编码选项**，一律按 UTF-8 解，所以：

**实测结论（2026-11-01，对本机真实状态页取样）**：门户返回的是 `charset=GB2312`，
按 UTF-8 硬解会让所有中文标签变成 `��ǰ��¼�˺ţ�` 这样的乱码。

但同一页里的**隐藏输入框是纯 ASCII**：

| 字段 | 页面原文 | 是否受乱码影响 |
| :--- | :--- | :--- |
| 账号 | `<input type="hidden" id="account" value="42512012@mobile"/>` | **不受影响** |
| IP | `<input type="hidden" id="ipaddr" value="10.138.108.230"/>` | **不受影响** |
| 登录时间 | 可见文本，值本身是 `2026-11-01 16:57:45` | **不受影响**（数字） |
| 中文标签 | `当前登录账号：` / `登录时间：` | ❌ 会乱码 |

所以三个正则**全部避开了中文**：动作 2 / 3 匹配 `id="..." value="..."`，动作 4 匹配纯数字时间。
这样即使门户坚持用 gb2312，快捷指令也能正确取到全部三个字段——**不需要退而求其次**。

| 情况 | 表现 | 对策 |
| :--- | :--- | :--- |
| 门户返回 gb2312（当前实测就是） | 中文标签乱码，但三个字段值正常 | 用上面三个 ASCII 正则，照常工作 |
| 门户改版去掉隐藏框 | 动作 2 / 3 匹配为空 | 退回兜底正则 `10\.\d{1,3}\.\d{1,3}\.\d{1,3}` + 匹配时间；仍失败就看原始 HTML |

> 也想看原始 HTML 的话，把「显示结果」的内容直接换成动作 1 的输出即可，
> 快捷指令会原样展示源码（这也是「无法完美格式化就显示关键行原文」的兜底做法）。

## 3. 指令三「校园网断开」

对应 Android 端的「断开认证（logoff）」。端点：`GET http://202.117.144.205:8601/snnuportal/logoff`
（`portal.rs:908` 的 logout，路径就是 `/snnuportal/logoff`，没有 .jsp 后缀）。

新建快捷指令，命名 **校园网断开**。

### 动作清单

| # | 动作名 | 关键参数 |
| :--- | :--- | :--- |
| 1 | 从菜单中选取 | 菜单项 `确认断开` / `取消` |
| 2 | 如果 | 选择结果 **是** `取消` → 「停止此快捷指令」 |
| 3 | 获取 URL 内容 | `GET http://202.117.144.205:8601/snnuportal/logoff` |
| 4 | 显示结果 | 插入动作 3 的输出原文 |
| 5 | 运行快捷指令 | （可选）跑一次 **校园网状态** 复查 |

### 逐步说明

#### 动作 1 · 防误触确认

快捷指令**没有**名为「确认」的原生动作，用下面两种之一实现二次确认：

- **「从菜单中选取」**（推荐，一次点击）：菜单项 `确认断开`、`取消`。
- **「要求输入」**（更严格，防手滑）：输入类型 文本，提示语「确认断开校园网？输入 YES 继续」，
  再「如果」判断输入 **是** `YES` 才继续。

#### 动作 2 · 取消即退出

「如果」选择结果 / 输入 **是** `取消`（或 **不是** `YES`）→ 加 **「停止此快捷指令」**。
这样点错了不会真的断网。

#### 动作 3 · 发起 logoff

**「获取 URL 内容」** → URL `http://202.117.144.205:8601/snnuportal/logoff`，方法 GET。

> 这个请求**会真的把你踢下线**，调试时别乱点。
> 它同时也是一次网络写操作——验证文档时只用只读的 userstatus.jsp，不要拿 logoff 做实验。

#### 动作 4 · 显示结果

**「显示结果」**，内容插入动作 3 的输出。门户一般返回一句结果页文本；
原样展示即可（同样是 gb2312 可能乱码的问题，见上一节的说明）。

#### 动作 5 · 复查（可选）

加 **「运行快捷指令」** → **校园网状态**，确认 IP 已经消失、账号变成 `未登录`。
这等价于 portal.rs 里 logout 之后的轮询复查逻辑（最多重试 3 次）。

## 4. 添加到主屏幕：手机上的「原生 App」体验

三条指令都能变成桌面图标，点一下直接执行，不需要先打开快捷指令 App。

**操作路径（三条各做一次）：**

1. 打开「快捷指令」App，找到 **校园网登录 / 校园网状态 / 校园网断开**
2. 点该快捷指令右上角的 `···`（或长按卡片）→ 选 **「分享」**（⤴ 图标）
3. 在分享菜单里向下找到 **「添加到主屏幕」**
4. 改图标名称（建议：`校园网登录` / `校园网状态` / `校园网断开`），可点左侧图标换图/换色
5. 右上角 **「添加」**

添加后桌面出现三个图标：

| 图标 | 点一下的效果 | 对应 Android 端 |
| :--- | :--- | :--- |
| 校园网登录 | 连 SNNU 时自动提交登录，弹「登录成功」 | 登录按钮 |
| 校园网状态 | 弹窗显示在线状态 / 账号 / IP / 登录时间 | 状态卡片 |
| 校园网断开 | 先确认，再 logoff | 断开按钮 |

> 体验说明：这三条跑起来后，日常操作就是**点图标 → 看结果**，和原生 App 的操作路径几乎一致。
> 差别只有两点：① 首次点图标时系统可能闪一下快捷指令 App 的启动画面；
> ② 结果以系统弹窗呈现，不是 App 内的界面。**功能等价，交互略糙**。

## 5. 个人自动化深化（iOS 17 / 18）

### 真实路径

1. 打开「快捷指令」App → 底部 **「自动化」** 标签（iOS 17 / 18 在底部标签栏最右侧）
2. 右上角 `+` → **「新建自动化」**（iOS 16 及更早写作「创建个人自动化」）
3. 触发器列表（iOS 17 / 18 实际存在的项）：
   **App、时间、闹钟、专注模式、无线局域网、蓝牙、到达、离开、通勤前、充电器、NFC、电子邮件、信息**
4. 选 **「无线局域网」** → **「选取」** → 勾选 `SNNU`（精确匹配，区分大小写）
5. 触发时机选 **「已连接」**（部分版本写作「加入时」；「未连接」是掉线那一刻，别选错）
6. **「下一步」** → **「添加操作」** → 搜索 **「运行快捷指令」** → 选 **校园网登录**
7. **「下一步」** → 关闭 **「运行前询问」** → 确认框选 **「不询问」**
8. **「完成」**

> 触发器清单与措辞会随系统版本微调，**以你手机上实际看到的为准**；
> 找不到「无线局域网」时，先确认系统版本 ≥ iOS 13，且该自动化没有被「停用」。

### 配方 A ·「加入 SNNU 自动登录」

这是本方案的关键：让快捷指令在你连上校园网时**自动**跑起来。

| 项 | 设置 |
| :--- | :--- |
| 触发器 | 无线局域网 → `SNNU` → **已连接** |
| 动作 | 运行快捷指令 → **校园网登录** |
| 运行前询问 | **关闭** |
| 运行结果通知 | 可关闭（登录成功与否看「显示提醒」即可） |

**验证**：关掉 Wi-Fi 再重新连上 SNNU，应看到快捷指令运行的横幅并自动完成登录。

### 配方 B ·「定时兜底：每早 8 点查一次状态」

Wi-Fi 触发器只在**加入网络那一刻**触发一次；会话挂着被踢下线时它不会重连。
定时自动化用来补这个洞——注意它**只能查/补登录，做不到秒级自愈**。

| 项 | 设置 |
| :--- | :--- |
| 触发器 | **时间** → 每天 → `08:00` |
| 动作 | 运行快捷指令 → **校园网状态**（想顺便补登录就再加一个 **校园网登录**） |
| 运行前询问 | **关闭** |

配置要点：

- 「时间」触发器的重复方式选 **「每天」**，时间设 `08:00`。
- 只查状态就够：如果早上发现掉线了，手动点一下主屏的「校园网登录」图标即可。
- 想全自动补登录，就在「校园网状态」之后串一个「校园网登录」——登录幂等，已在线时重复执行无副作用。
- 同理可加一条**每小时**的状态检查；但触发太密会频繁弹窗，建议只在需要的时候开。

## 6. 端口切换

主端口 8601 不通时，把三条指令里 URL 的端口换成 8602，或依次试：

`8601` → `8602` → `8603` → `8605` → `8609` → `8604` → `8606` → `8607` → `8608` → `8610` → `8600`

也可以复制一份快捷指令命名为「校园网登录（备用）」，在自动化里先跑主端口、失败再跑备用。

> 程序自己会在多个端口间自动探测并记住可用的那个；快捷指令没有这个能力，
> 端口写死在哪条指令里，就只能手动改。这是快捷指令相对桌面端的固有差距。

## 7. 与上游 Android 1.0.0 的功能对齐表

图例：**✅ 覆盖**（功能与上游等价）｜**🟡 等效**（能达成目的，但实现方式不同或有损耗）｜**❌ 做不到**（系统限制，附原因）

| 功能 | 上游 Android 1.0.0 | iOS 快捷指令 | 结论 |
| :--- | :--- | :--- | :--- |
| ① 登录（含运营商选择） | 界面选择 校园网 / 移动 / 联通，yys 随请求提交 | 指令一「校园网登录」：动作 5 菜单选运营商 → `POST /snnuportal/login` 提交 yys | ✅ **覆盖** |
| ② 查在线状态（账号 / IP / 登录时间） | 状态卡片实时展示，解析 userstatus.jsp | 指令二「校园网状态」：`GET userstatus.jsp` + 「匹配文本」提取隐藏框 `account` / `ipaddr` + 时间正则 | 🟡 **等效**：三个字段全部可取（正则走 ASCII，gb2312 乱码不影响）；差别只在展示为弹窗而非常驻卡片 |
| ③ 断开认证（logoff） | 断开按钮 → `GET /snnuportal/logoff` | 指令三「校园网断开」：确认后 `GET /snnuportal/logoff` | ✅ **覆盖**（多了一层防误触确认） |
| ④ 自动登录开关 | 应用内开关，关闭即停前台服务 | 靠「自动化」列表里的**启用/停用**开关，或直接删掉自动化；主屏图标仍可手动执行 | 🟡 **等效**：没有应用内开关，开关挪到了系统「自动化」里，概念一致但入口不同 |
| ⑤ 掉线重连（会话被踢后自动恢复） | 前台服务持续探测 + 断线即重登 | **做不到** | ❌ **做不到**。原因：iOS 不允许第三方后台常驻轮询；「无线局域网」触发器只在**加入网络那一刻**触发一次，已连着 Wi-Fi 但会话过期**不会**触发；没有「网络可用性变化」这类可挂载的触发器。只能靠「时间」自动化兜底（最小粒度分钟级）或手动点图标 |
| 主屏一键操作 | 桌面小部件 / 应用图标 | 三条指令均「添加到主屏幕」，点图标即执行 | 🟡 **等效**：见第 4 节，功能等价、交互略糙 |
| 端口自动探测与记忆 | 11 端口自动探测，记住可用端口 | 需手动改 URL 端口 | ❌ **做不到**（快捷指令无循环探测 + 持久化状态的合理实现） |
| 验证码场景 | 归类为验证码错误并暂停 | 同样失效 | 🟡 一致受限 |

**一句话结论**：日常四件事（登录 / 查状态 / 断开 / 自动登录触发）iOS 都能做到；
**唯一硬缺口是「掉线后主动重连」**——这是 iOS 系统限制，不是实现偷懒，
换成任何第三方 App（包括自签 ipa）同样做不到，详见 [ipa-roadmap.md](ipa-roadmap.md)。

## 8. 版本差异与已知限制

> 以下为文档编写时的行为描述，**未在全部真机上逐一实测**，请以你当前系统版本的界面措辞为准。

| 项目 | 说明 |
| :--- | :--- |
| 「无线局域网」触发器 | iOS 13 起提供。仅在**加入指定网络**时触发一次；掉线重连、Wi-Fi 已连着但会话过期**都不会**触发 |
| 「运行前询问」 | iOS 15 起个人自动化可彻底关闭该开关实现全自动；iOS 13 / 14 的 Wi-Fi 触发器可能仍会弹通知，需点一下 |
| iOS 17 / 18 | 触发器措辞为「已连接 / 未连接」，入口为「自动化 → 新建自动化」；动作名称为「获取网络详情」；未逐版本实测，界面可能微调 |
| 后台运行 | 快捷指令**不能**在后台常驻轮询，系统会杀掉长期后台任务。这是 iOS 的硬限制 |
| 掉线自愈 | **做不到**。只能靠重新加入网络或定时自动化兜底，无法像桌面端那样秒级重连 |
| 状态页编码 | 门户返回 gb2312，快捷指令按 UTF-8 解会让中文标签乱码。本方案的正则只匹配 ASCII 隐藏框（`id="account"` / `id="ipaddr"`）与数字时间，因此功能不受影响，见第 2 节 |
| 状态页格式 | 老式 JSP + HTML 表格，没有 JSON 接口。正则提取对页面改版敏感，门户一改版可能要重调正则 |
| HTTP 明文 | 门户是 `http://`，快捷指令允许明文请求 |
| 验证码 | 门户若开启验证码，接口式登录全部失效，快捷指令同样失效（程序会归类为验证码错误） |
| 多设备 | 每台设备要各自建一次；账号密码不跨设备共享（除非开 iCloud 同步） |

## 10. 常见问题

**Q：提示「无法连接到服务器」？**
多半是不在校园网内（走 4G 或连了别的 Wi-Fi）。先确认手机能打开 `http://202.117.144.205:8601/snnuportal/login.jsp`。

**Q：提示账号或密码错误？**
先用桌面端验证一次账号密码，确认后再填进快捷指令。注意别带空格或全角字符。

**Q：yys 到底填什么？**
看你在认证页面上选的运营商。选「移动」填 `mobile`（本方案菜单的默认项），选「校园网」留空，选「联通」填 `unicom`。
**电信出口已停用，不要填 `telecom`。**

**Q：状态指令显示「当前未登录」，但我明明连着 Wi-Fi？**
连着 Wi-Fi ≠ 已通过门户认证。多半是会话过期了，点一下主屏的「校园网登录」图标即可。

**Q：状态指令显示的值对不对，但页面中文是乱码？**
门户返回 gb2312，快捷指令按 UTF-8 解会让中文标签乱码。本方案的正则**刻意只匹配 ASCII 隐藏框**，
所以账号 / IP / 登录时间三项照常正确，乱码不影响功能。原理见第 2 节「关于 gb2312 / HTML 源码的局限」。

**Q：断开之后 Wi-Fi 还连着，是不是没生效？**
logoff 断的是**门户认证会话**，不是 Wi-Fi 连接（和 Android 端一样）。断开后网页打不开是正常现象，重新登录即可。

**Q：能分享给室友吗？**
可以导出分享，但**分享前务必清空「文本」动作里的学号和密码**。

**Q：为什么不做一个 App？**
见 [ipa-roadmap.md](ipa-roadmap.md)——自签成本远高于收益，且系统限制决定了它做不到后台自愈。
