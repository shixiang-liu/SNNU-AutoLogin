# iOS 方案二：自签 ipa 路线

> 结论先写在最前面：**不推荐**。请直接用 [快捷指令方案](shortcuts-guide.md)。

---

## 0. iOS 端能做什么、不能做什么

| 能力 | 能否实现 | 原因 |
| :--- | :--- | :--- |
| 加入 SNNU 时自动登录 | ✅ 能 | 与快捷指令等效：自动化触发 + 一次 HTTP POST |
| 手动登录 / 查在线状态 | ✅ 能 | 普通表单 POST + 页面解析，逻辑可移植 `portal.rs` |
| 断开认证 | ✅ 能 | `GET /snnuportal/logoff` |
| **后台常驻、掉线秒级自愈** | ❌ **不能** | 见下方系统限制 |
| **主动连接 / 切换 Wi-Fi** | ❌ **不能** | 无公开 API |
| 上架 App Store | ❌ **不能** | 后台监控类过不了审核 |

### 系统限制（硬性，非工程量问题）

1. **无法主动连接 Wi-Fi。** 第三方 App 没有公开 API 去连接某个 SSID。
   `NEHotspotConfiguration`（Network Extension）能添加热点配置，但需要 Hotspot Configuration 权限，
   面向 App Store 分发时会被严格审查，也不适用于「校园网通用工具」这类场景；
   它同样不能枚举周边网络或静默切换。
   > 对比：Android 端也只能用 `CHANGE_WIFI_STATE` / `WifiNetworkSuggestion` **请求**连接，由系统决定；
   > 且不申请定位权限时读不到 SSID。iOS 连这个能力都没有。
2. **无法后台常驻监控。** iOS 会挂起后台 App。长期运行只能申请特定后台模式（VoIP、定位、音频等），
   而「持续监控网络并自动登录」不属于任何一种合法后台模式。
   桌面端托盘常驻 + 秒级重连的体验，在 iOS 上不存在对应能力。
3. **Captive Portal 由系统接管。** 连上需要认证的 Wi-Fi 时，iOS 会自己弹「登录到网络」页面（CNA），
   由系统 WebView 完成认证，第三方 App 无法介入或替换这个过程。

### 审核限制

后台持续联网监控类 App 无法通过 App Store 审核（违反后台模式与电池相关条款）。
因此即使做出来，也只能自签侧载，永远进不了 App Store。

## 1. 无 Mac 时的三条实际路径

前提：**本机是 Windows，没有 Mac、没有 Xcode**。做 ipa 需要「编译」和「签名」两步，
两者都绕不开 macOS 工具链，所以只能借云。

### 路径 A：云 Mac 构建 + 免费证书自签（7 天重签）

用 Codemagic / GitHub Actions 的 macOS runner（或任意云 Mac 免费额度）跑 `xcodebuild`，
用 Apple 免费开发者账号（个人团队）导出的证书与描述文件签名，产出 ipa 后侧载。

| 项 | 内容 |
| :--- | :--- |
| 成本 | 云 Mac 免费额度（Codemagic 每月约 500 分钟；GitHub Actions 公共仓库免费）+ 免费 Apple ID（0 元） |
| 有效期 | **签名 7 天过期**，到期 App 打不开，必须重签并重装 |
| 设备数 | 免费账号可注册设备很少（约 3 台），且每年有次数限制 |
| 需要 | 一台能上网的电脑（本机即可）+ 数据线 + 一台 iPhone |
| 痛点 | 每 7 天重来一次；证书与描述文件管理繁琐；免费账号不能推送 |
| 适用 | 想验证「做个 App 到底值不值」的一次性实验 |

### 路径 B：AltStore / SideStore 侧载 + 自动重签

Windows 上装 AltServer，用 Apple ID 给 ipa 签名后通过 Wi-Fi 装到 iPhone；
SideStore 可在设备上自签，配合 StosVPN 实现无电脑续签。

| 项 | 内容 |
| :--- | :--- |
| 成本 | 0 元（免费 Apple ID） |
| 有效期 | 同样 7 天，但可用 `.refresh` 后台刷新 / 定时任务自动重签 |
| 设备数 | 免费账号限制，通常 3 台以内 |
| 需要 | Windows 上常驻 AltServer，或手机上常驻 SideStore + StosVPN |
| 痛点 | 免费账号最多同时 3 个自签 App；AltServer 需与手机同一 Wi-Fi；重签失败就打不开；系统升级后可能失效 |
| 适用 | 愿意长期折腾、确实需要原生 App 的用户 |

### 路径 C：TestFlight / 付费开发者账号

| 项 | 内容 |
| :--- | :--- |
| 成本 | Apple Developer Program **688 元 / 年** |
| 有效期 | TestFlight 构建 90 天有效，可反复发版；正式分发无 7 天限制 |
| 设备数 | 内部测试 100 台 / 外部测试 10000 人 |
| 需要 | 付费账号 + 仍需 macOS 工具链（或云构建） |
| 痛点 | 要花钱；外部测试每次构建仍需审核；上架 App Store 依旧过不了后台监控这条红线 |
| 适用 | 已有付费账号、且想分发给一批同学的场景 |

### 三条路径对比

| 维度 | A 云构建 + 免费证书 | B AltStore / SideStore | C TestFlight / 付费号 |
| :--- | :--- | :--- | :--- |
| 花钱 | 0 | 0 | 688 元 / 年 |
| 有效期 | 7 天 | 7 天（可自动续签） | 90 天 / 长期 |
| 需要 Mac | 云 Mac（免费额度） | 不需要，Windows 即可 | 云 Mac |
| 维护成本 | 高（每 7 天重来） | 中（自动续签，可能失败） | 低 |
| 上手难度 | 高 | 中 | 中 |
| 能否上架 | 否 | 否 | 否（后台监控类过不了审核） |
| 推荐度 | ⭐ | ⭐⭐ | ⭐（除非已有付费号） |

## 2. 就算做出来，功能也长这样

```
[ 校园网助手 ]
  当前 Wi-Fi：SNNU
  状态：在线（账号 2023xxxxxx）
  [ 立即登录 ]  [ 断开连接 ]  [ 刷新状态 ]
```

再加一个「加入 SNNU 时自动登录」的触发——而这件事**快捷指令已经免费做到了**，且不用 7 天重签。

对应到现有实现的可移植性：

| 现有能力 | iOS App 可移植性 |
| :--- | :--- |
| 表单登录（`portal.rs` 的 5 字段 POST） | ✅ 直接搬 |
| 状态查询（`userstatus.jsp`） | ✅ 直接搬 |
| 断开（`/snnuportal/logoff`） | ✅ 直接搬 |
| 后台常驻掉线自愈 | ❌ 系统不允许 |
| Wi-Fi 连接与切换 | ❌ 无公开 API |

## 3. 结论与推荐

1. **快捷指令已覆盖 iOS 用户约 90% 的需求**：加入 SNNU 即自动登录，一次配置长期可用，
   零成本、零维护、不占用 3 个自签名额、不怕 7 天过期。
2. **ipa 路线收益极低**：能多出来的只有「一个原生界面」和「手动按钮」，
   代价却是每 7 天重签、设备数限制、证书管理、系统升级兼容性风险。
3. **真正缺失的能力（后台自愈、主动连 Wi-Fi）是 iOS 系统限制，不是工程量问题**——
   无论花多少钱、写多少代码都补不上。
4. **因此推荐**：iOS 用户走 [快捷指令方案](shortcuts-guide.md)；
   需要 7×24 秒级自愈的，请用 Windows 桌面端、Linux 无头版或 Android 端。

> 如果你仍然想试 ipa：建议按路径 B（AltStore）先做最小验证版，
> 确认「装了也没多出什么功能」之后，再决定要不要投入。
